# Как участвовать в разработке

Спасибо, что хотите помочь! Проект развивается вместе с сообществом: баг-репорты, идеи,
переводы, документация и код одинаково ценны.

## С чего начать

1. Посмотрите [открытые issues](https://github.com/kirillzakup/seller-bot-mini-crm/issues) —
   задачи для новичков помечены `good first issue`.
2. Хотите сделать что-то крупное — сначала откройте issue и опишите идею, чтобы обсудить
   подход и не делать работу дважды.
3. Сделайте форк, создайте ветку от `main` (`feature/…` или `fix/…`), внесите изменения и
   откройте пул-реквест.

## Окружение

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
python -m app.main                                   # http://localhost:8000/admin, admin / admin
```

## Перед пул-реквестом

```bash
PYTHONIOENCODING=utf-8 python -m pytest -q
python -m ruff check app/ tests/
```

- Все тесты зелёные, линтер чистый.
- Новая функциональность — с тестами в `tests/` (pytest, `asyncio_mode = auto`).
- Новая колонка в существующей таблице — в список `wanted` в
  `app/db/base.py::_ensure_sqlite_columns`.
- Никаких токенов, ключей, телефонов и данных реальных клиентов — ни в коде, ни в тестах,
  ни в скриншотах. Для примеров используйте `example.com`, `+7 700 000 00 00` и вымышленные имена.

## Стиль кода

- Python 3.11+, длина строки 100, линтер `ruff`.
- Один модуль — одна ответственность; файлы до ~400 строк, функции до ~50.
- Комментарии объясняют «почему», а не «что», и пишутся по-русски. Тексты интерфейса — на русском.
- То, что должно случиться гарантированно (заявка, оплата, выдача доступа), делается кодом,
  а не инструкцией в промпте.
- aiogram: сработавший хендлер останавливает цепочку — фильтры делайте узкими в декораторе.

## Сообщения коммитов

Формат `тип: описание` на русском или английском, типы: `feat`, `fix`, `refactor`, `docs`,
`test`, `chore`, `perf`. Пример: `feat: раскладка заявок по темам из админки`.

## Сообщить об ошибке

В issue укажите: что делали, что ожидали, что получили, версию Python и способ запуска
(локально / Docker), фрагмент лога без секретов.

Уязвимости не публикуйте в issues — напишите владельцу репозитория через GitHub.
