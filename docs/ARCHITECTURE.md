# Архитектура

Один процесс (и один Docker-контейнер): Telegram-бот на long-polling, FastAPI (админка, вебхуки
Meta и платёжных шлюзов, страница оплаты, лендинги) и планировщик APScheduler. База — SQLite в
режиме WAL через SQLAlchemy async; при росте меняется на PostgreSQL через `DATABASE_URL`.

## Модули

| Папка | Роль |
|---|---|
| `app/main.py`, `app/config.py`, `app/db/` | Запуск приложения, настройки из `.env`, модели и движок БД |
| `app/channels/` | Интерфейс `Messenger` и адаптеры: Telegram, WhatsApp + Instagram (Meta, один вебхук `/webhooks/meta`); `dispatch.py` — общий приём входящих для всех каналов |
| `app/sales/` | ИИ-менеджер: цикл «модель + инструменты» (`ai_manager.py`, `tools.py`, `llm.py`), промпты и методика (`prompts.py`), портрет клиента (`client_profile.py`, `adaptation.py`), стиль, форматирование текста и речи |
| `app/services/` | Бизнес-логика: заказы, заявки и карточки, утренняя сводка, рассылки, дожимы, отчёты, медиатека и документы, настройки, уведомления |
| `app/bot/handlers/` | Telegram: старт, каталог, оплата, чат с ИИ, инбокс операторов (ответ клиенту прямо из темы группы), кнопки заявок |
| `app/admin/` | Веб-админка: Jinja2-шаблоны + HTMX + Tailwind, вход по логину и паролю из `.env` |
| `app/payments/` | `PaymentProvider` и реализации: ручная оплата по чеку, ссылка, Halyk ePay, FreedomPay, ЮKassa, CryptoBot; общий вебхук `/webhooks/pay/{provider}` и страница `/pay/{код}` |
| `app/fulfillment/` | Выдача после оплаты: текст/ссылка, одноразовый инвайт в закрытый Telegram-канал |
| `app/voice/` | Голос через ElevenLabs: распознавание входящих и голосовые ответы |
| `app/appapi/` | JSON-API для мобильного приложения операторов (bearer-токен) |

## Главные потоки

### Сообщение клиента
`канал` → `dispatch_incoming` → перехваты до модели (просьба показать фото, реакция, голосовое) →
`ai_manager.handle_text` → модель вызывает инструменты (`tools.py`) → ответ уходит через
`Messenger` того же канала. Если оператор перехватил диалог, бот молчит, а сообщение зеркалится
в тему клиента в Telegram-группе «Диалоги».

### Заявка менеджеру
Все передачи клиента человеку (`escalate_to_operator`, `ask_admin`, `request_callback`, просьба
фото, форма на сайте) сходятся в `leads_service.record_handoff` / `record_web_lead`. У клиента
одна открытая заявка: новая причина дописывается в неё, карточка в группе перерисовывается на
месте (`refresh_card`), а не дублируется.

Стадии: `new` → `in_work` → (`waiting`) → `sale` / `reject` / `not_target`. Кнопки собирает
`card_kb` по стадии; нажатия — `app/bot/handlers/leads.py`. Сумму, причину, дату ожидания и «что
сделано» бот спрашивает через ForceReply со служебной меткой `⟦заявка #N тип⟧`; ответ ловит
узкий фильтр `_is_ask_reply`. Забранную карточку меняет только её владелец.

`leads_reminders.py`: каждые 5 минут возвращает заявки из ожидания новым сообщением внизу темы;
в 9:00 шлёт мини-отчёт и списки «Не забраны» / «В работе» со ссылками на карточки.

### Оплата и выдача доступа
`create_payment` → `orders.create_order` → ссылка на `/pay/{код}` → клиент платит (шлюз или
перевод + чек) → `orders.confirm_payment` (из вебхука шлюза, кнопки оператора или админки) →
статус `PAID` → `fulfill`. У ИИ нет инструмента выдачи доступа: выдача возможна только после
`PAID`, повторные вебхуки безопасны (идемпотентность по `order_id`).

## Фоновые задачи (`app/scheduler.py`)

| Задача | Частота |
|---|---|
| Возврат заявок из ожидания | 5 мин |
| Сверка ожидающих оплат, отложенные напоминания клиентам | 10 мин |
| Дожим молчащих клиентов, проверка часа утренней сводки | 15 мин |
| Брошенные заказы, истечение подписок | 30 мин |
| Дни рождения | 6 ч |
| Обновление токена Instagram | 12 ч |
| Автоанализ скрипта продаж | 24 ч |

## Где хранится конфигурация

- `.env` — то, что нужно до старта: токен бота, адрес, пароль админки, секрет сессий, ИИ по умолчанию.
- Таблица `settings` — всё, что владелец меняет в админке: персона, скрипт, ключи каналов и
  шлюзов, чат менеджеров, расписание напоминаний. Значения по умолчанию — `settings_service.default_settings()`.
- `runtime/.env` — секреты, которые админка сохраняет из интерфейса (не коммитить).

## Расширение

- **Новый канал:** реализуйте `Messenger` в `app/channels/`, зарегистрируйте в `registry.py`,
  входящие отдавайте в `dispatch_incoming`.
- **Новый платёжный шлюз:** реализуйте `PaymentProvider` в `app/payments/` и добавьте в реестр.
- **Новый способ выдачи:** реализуйте `FulfillmentProvider` в `app/fulfillment/`.
- **Новый инструмент ИИ:** опишите схему в `TOOLS` и обработчик в `run_tool` (`app/sales/tools.py`).
